# Triage

Categorize and evaluate issues on your issue tracker.

Verify that `/setup-matt-pocock-skills` was run to configure your issue tracker settings.

Add this header note to all triage comments posted to an issue tracker:
```
> *This was generated by AI during triage.*
```

---

## Labels & Roles

Every triaged issue MUST receive exactly 1 category label and 1 state label:

### Category Labels
- `bug`: Something is broken or returning errors.
- `enhancement`: A new feature request or improvement.

### State Labels
- `needs-triage`: New issue awaiting maintainer evaluation.
- `needs-info`: Waiting for the reporter to provide missing details.
- `ready-for-agent`: Clear specification ready for an automated agent to build.
- `ready-for-human`: Requires manual human action, access, or decision.
- `wontfix`: Rejected, out of scope, or already implemented.

---

## Process

1. **Read the issue:** Review the issue description, comments, and reproduction steps.
2. **Check for existing code:** Search the codebase to see if the feature already exists. If it exists, mark the issue as `wontfix` and point to the existing code.
3. **Check out-of-scope rules:** Check `.out-of-scope/` files to see if this request was previously rejected.
4. **Verify bugs:** Reproduce reported bugs before marking issues as `ready-for-agent`.
5. **Interview if needed:** Run `/grilling` to clarify ambiguous requests.
6. **Apply labels and post summary:** Update issue labels and leave a concise summary comment.
