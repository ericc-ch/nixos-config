---
name: simple-english
description: Write plain, human-sounding prose. Use when drafting copy, specs, tickets, or when the user asks to restate something simply, cut jargon, or write like a human.
---

Write like one human talking to another. Be concrete, short, and clear.

- Prefer exact names over jargon and pronouns. Repeat the service, variable, or system name instead of "it" or "this".
- Prefer active voice. Name who does the action.
- Prefer present tense and direct address. State what the system does now ("returns 404", not "will return 404"), and use imperative commands ("Run the build", not "We should run").
- Prefer one actor and one action per sentence. Split compound actions.
- Prefer specific facts. Skip vague impact language, condescension, and filler ("basically", "currently", "in order to", "simply", "just", "easy").
- Prefer short sentences.
- End when the information ends. No formulaic closers.
